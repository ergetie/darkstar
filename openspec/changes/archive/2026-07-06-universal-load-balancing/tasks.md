## 4. Load balancer core

All in new file `executor/load_balancer.py`, a class holding its own state between ticks, with one public method called from `_tick` (input: `SystemState`, the intended per-device EV targets from step 3, shed-able load states; output: capped EV targets + shed/restore commands + a status object). No HA calls inside — it only transforms decisions; actuation stays in existing dispatch paths.

- [x] 4.1 Headroom: `headroom_a[p] = main_fuse_a − state.grid_current_a[p]` per phase; binding headroom for a load = min over that load's phases (EV: `active_phases` from 2.2; on/off loads: declared `phases`). Done when: unit test reproduces the spec scenario (L1=18/L2=5/L3=5 at 20 A fuse → binding 2 A for 3-phase EV).
- [x] 4.2 EV capping, decrease side: if binding headroom < 0, new setpoint = current setpoint + binding headroom (i.e. reduced), floored at `min_current_a`; applied same tick, no rate limit. Done when: stove-spike test (16 A charging, headroom −6) yields ≤ 10 A.
- [x] 4.3 EV capping, increase side: only when every relevant phase is below `resume_margin_percent` of fuse; at most `increase_step_a` per tick; never above `min(max_current_a, planner target from 3.2)`. Done when: tests cover margin-blocked increase and step-limited ramp to target.
- [x] 4.4 Pause/resume state machine: pause when binding headroom cannot sustain `min_current_a`; record pause timestamp; resume only when `resume_delay_s` elapsed AND margin condition holds for the minimum current. Done when: test with a 30 s dip shows no resume before 120 s.
- [x] 4.5 Shedding: when EV is paused/at-floor and a phase is still over fuse, shed on/off loads declared on that phase, lowest `priority` first; restore strictly in reverse order under the same delay+margin gate. Output shed/restore commands as data; wire actuation: water heater → existing minimum-target write path, custom entity → its configured off value (reuse the `ExcessPVCustomEntityConfig` on/off pattern). Done when: ordering test (shed p1 then p2 → restore p2 then p1) passes.
- [x] 4.6 Stale-sensor fail-safe: if any `grid_current_updated_at` is older than `sensor_stale_after_s`, output EV = `min_current_a` immediately; if staleness persists ≥ `resume_delay_s`, output pause. Done when: tests cover both stages.
- [x] 4.7 Wire into `_tick` (`executor/engine.py:1020`): call the balancer after controller decision and override evaluation, before dispatch; skip entirely (zero behavior change) unless `load_balancing.enabled` and prerequisites hold. Done when: with the feature disabled, a full-tick integration test produces byte-identical decisions to main.
- [x] 4.8 Unit test for the "total kW fine, one phase over" case: total power below `max_power_kw` but L1 over fuse → balancer still throttles.

## 9. Verification remediation (post-verify findings, 2026-07-06)

- [x] 9.1 **[CRITICAL] Expose current-type EV charging in the charger editor.** The backend fully implements `type: current` but the EV charger editor (`frontend/src/pages/settings/components/EntityArrayEditor.tsx`) cannot configure it, so the feature is unusable end-to-end (users hit "type 'current' but no current_entity" on save with no field to fix it). Change the `EVChargerEntity` type union (`:35`) to `'binary' | 'current'` (drop dead `'variable' | 'constant'`); add `current_entity`, `min_current_a`, `max_current_a`, `phases` (and optional `phase_sensor_l1/l2/l3`) to the interface + `createEvCharger` defaults; add a "Current (dynamic amps)" option to the EV Load Type dropdown (`:531-537`); when type is `current`, render a `current_entity` HA-number picker (required), min/max current number inputs, and L1/L2/L3 phase checkboxes; remove the stale "Variable power control is not yet implemented" warning banner (`:541-547`). Done when: a charger can be set to current type with a current_entity in the UI, saved without validation error, and round-trips through reload.
- [x] 9.2 **[WARNING] Failure record must not be throttled away.** An EV charge failure sets `record.success=0` (`executor/engine.py:1587-1590`) but `ev_charge_failed` is not a trigger in `_should_log_execution` (`:1990`), so the failing tick's `success=0` record is usually discarded unless it coincides with the 15-min heartbeat. Add `ev_charge_failed` (or `not record.success`) as an explicit log trigger, and fix the now-inaccurate comment in `backend/monitors.py:251-256` (which claims failures are never throttled). Done when: a test asserts a failure tick always persists a `success=0` record even mid-slot.
- [x] 9.3 **[WARNING] Stale-pause recovery must honor the anti-flap delay.** A stale-induced full pause records into `_ev_stale_since`, not `_ev_paused_at` (`executor/load_balancer.py:200, 209`), so when the sensor returns fresh, charging resumes at floor immediately, bypassing `resume_delay_s`. Make recovery from a stale-induced pause go through the same resume-delay + margin gate as an overload pause. Done when: a test shows a sensor flapping around the 30 s staleness boundary does not resume before `resume_delay_s`.
- [x] 9.4 **[WARNING] Status card margin line must reflect configured `resume_margin_percent`.** `LoadBalancerStatusCard.tsx:95` hardcodes `const margin = 90`. Add `resume_margin_percent` to the balancer status payload (`get_load_balancer_status` in `executor/engine.py`) and the `LoadBalancerStatusResponse` type in `frontend/src/lib/api.ts`, and read it in the card instead of the hardcoded constant. Done when: changing `resume_margin_percent` in settings moves the rendered margin line.
