# Tasks: Excess PV Priority Dispatch

> **Prerequisite:** the `universal-load-balancing` change MUST be fully implemented and verified first. This change consumes its EV `type: current` config fields (`current_entity`, `min_current_a`, `max_current_a`, `phases`), its ampere actuation path, its ramp/pause/resume (anti-flap) machinery, and its balancer cap. If any of those names differ in the merged implementation, adapt references here to the merged names — do not re-invent the mechanisms.
>
> Conventions used below: "3-phase minimum" = `min_current_a × 3 × 230 / 1000` kW (≈ 4.14 kW at 6 A); "1-phase minimum" = `min_current_a × 230 / 1000` kW (≈ 1.38 kW). Never hardcode 4.14/1.38 — always derive from config.

## 3. Executor: surplus tracking, custom-entity list, phase switching

- [x] 3.1 In `executor/engine.py` slot parsing (`_load_slot`-equivalent around line 1653 where `ev_charging_kw`/`ev_charger_plans` are read): read the new per-slot `ev_surplus_kw` mapping into the slot object; default empty. A charger is "surplus-eligible this slot" when its id maps to a value > 0.
- [x] 3.2 In `executor/engine.py`: implement the surplus feedback controller for surplus-eligible slots (design D3). Each tick, compute live surplus from `SystemState`: dual meters → `current_export_kw − current_import_kw`; net meter → `−grid_power`. If surplus > entry's `surplus_deadband_kw`: raise the desired EV setpoint by `floor(surplus_kw × 1000 / (230 × active_phases))` A, subject to the increase-slow ramp from `universal-load-balancing`. If surplus < −deadband (importing): lower the setpoint by the equivalent amps immediately (no ramp limit). Within the deadband: hold. The planner's `ev_surplus_kw` value is eligibility only — never dispatch it open-loop.
- [x] 3.3 In `executor/engine.py`: order of operations each tick for a surplus-eligible charger MUST be: surplus feedback proposes amps → phase-mode state machine (task 3.5) may adjust mode/conversion → balancer cap from `universal-load-balancing` clamps → dispatch. Add an executor-level comment stating this ordering; the balancer clamp is authoritative.
- [x] 3.4 In `executor/engine.py`: pause/resume for sustained shortfall — when the feedback-computed setpoint falls below `min_current_a × active_phases` equivalent power AND phase switching cannot lower the minimum further (already 1-phase, or unavailable), invoke the shared pause primitive from `universal-load-balancing`. Resume only when measured surplus ≥ 1-phase minimum + resume margin continuously for the shared resume delay. Preserve EV source isolation (existing `discharge_kw=0` forcing at ~line 1300) for surplus charging — verify it triggers on surplus-mode charging detection, not only on `ev_charging_kw > 0` (surplus slots have `ev_charging_kw = 0`; extend the detection condition to include active surplus mode).
- [x] 3.5 In `executor/engine.py` (+ `executor/actions.py` for the write): implement the phase-mode state machine (design D5) as a small class or function with explicit state: `commanded_mode` (1/3/unknown), `last_switch_time`. Inputs each tick: target power, hysteresis, dwell. Rules: below `(3ph_min + hysteresis_kw)` continuously for the dwell window → command 1-phase; above it continuously for the dwell window → command 3-phase; never command within `min_dwell_s` of the last switch; never command when `phase_switching_enabled` is false, `phase_mode_entity` is empty/unavailable, or the charger is binary. On write failure or unavailable entity: log once, set mode to unknown, use configured `phases` for conversions, stop attempting switches until the entity recovers. Add a `set_ev_phase_mode` dispatcher method in `executor/actions.py` following the existing typed-helper pattern (`set_select_option`/`set_number`), including read-back verification.
- [x] 3.6 In `executor/engine.py`: all kW↔A conversions for a phase-switchable charger use the commanded phase count (fallback: configured `phases`), and once the charger's measured per-phase draw (from `universal-load-balancing`'s phase accounting) shows fewer active phases than commanded, use the measured count for power accounting.
- [x] 3.7 In `executor/engine.py` (around lines 1414-1425): generalize custom-entity toggling from the single `config.excess_pv.custom_entity` to iterating all `custom_entity` entries in `priority[]`, including the `SLOT_FAILURE_FALLBACK` off-path. - [x] 3.8 Ensure balancer/surplus state transitions (surplus mode enter/exit, pause/resume, phase-mode switch, entity-unavailable fallback) are logged through the always-log-transitions channel established by `universal-load-balancing`'s execution-log throttling, each with a human-readable reason string.
- [x] 3.9 Write executor unit tests: (a) feedback raises within ramp limit on export, lowers immediately on import, holds inside deadband — for BOTH `grid_meter_type: dual` and `net`; (b) balancer cap clamps the surplus proposal; (c) pause on sustained shortfall, no resume before delay, resume after stable surplus; (d) phase state machine — switch down, switch up, hysteresis hold, dwell lockout, unavailable-entity fail-safe, disabled flag; (e) conversions follow commanded then measured phase count; (f) two custom entities toggled independently incl. slot-failure fallback; (g) EV source isolation active during surplus charging; (h) non-eligible slots behave exactly as before (regression guard).
