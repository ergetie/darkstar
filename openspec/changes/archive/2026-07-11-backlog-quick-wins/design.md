# Design: backlog-quick-wins

## Context

Five independent backlog quick wins batched into one change. All were triaged 2026-07-10 with the user: fixes and cleanups only, no new features. Verified facts driving the design:

- `POST /api/simulate` (`backend/api/routers/schedule.py:524`) is broken (`'dict' object has no attribute 'iterrows'`) and dead: its only callers are `frontend/src/pages/archive/Planning.tsx` and `Lab.tsx`, which are unrouted and imported by nothing. `planner/simulation.py` has exactly one production consumer — this endpoint. User chose deletion over repair, including all three archived pages (`Learning.tsx` also confirmed dead and approved for deletion).
- `scripts/insert_mock_price_forecasts.py:52` writes timezone-naive `slot_start` via `strftime`, breaking joins with `slot_observations` (always timezone-aware). Dev/test-only.
- `openspec validate --specs` fails on 5 specs: `startup-wizard` (5× missing SHALL/MUST + brief Purpose), `sensor-configuration` (2× missing SHALL/MUST), `aurora-corrector` (1× missing SHALL + missing scenario), `executor` (2× missing scenario), `planner` (1× missing scenario). Documentation lint only — the capabilities are implemented.
- `GET /api/ev/chargers` awaits three HA REST reads (plug/SoC/power) sequentially per charger; helpers are already async and gather-ready. Endpoint is polled by the dashboard EV tab.
- `/api/ha/average` takes ~1.3 s on cache miss because `_fetch_ha_history_avg` (`backend/api/routers/ha.py:39-40`) and `get_load_profile_from_ha` (`backend/core/ha_client.py:618-619`) request maximal-detail history (`significant_changes_only: False`, `minimal_response: False`).

## Goals / Non-Goals

**Goals:**
- Remove the dead simulate endpoint and every artifact that exists only to serve it.
- Make mock price-forecast data timezone-correct.
- Make `openspec validate --specs` pass cleanly.
- Cut `GET /api/ev/chargers` latency by parallelizing HA reads.
- Shrink the two targeted HA history fetches without changing computed averages.

**Non-Goals:**
- Fixing the simulate endpoint's dict/DataFrame bug (deleted instead).
- Touching the learning backfill (`backend/learning/backfill.py`) or `get_energy_from_power_history` fetch flags — training data and energy integration keep full detail deliberately.
- Any new features, UI changes to live pages, or dashboard work.
- Frontend rebuild artifacts (`backend/static/assets/*.js` are build outputs, regenerated by CI/build — not hand-edited).

## Decisions

**D1 — Delete, don't fix, the simulate stack.** Endpoint + `planner/simulation.py` + `tests/planner/test_simulation.py` + `api.simulate` client function + 3 archive pages. Alternative (fix the dict→DataFrame mismatch) rejected: it repairs code with zero callers. Route snapshot test (`tests/api/test_route_snapshot.py`) and smoke test (`tests/api/test_endpoint_smoke.py`) lose their simulate entries — this is the spec-level route-list change captured in the `router-structure` delta.

**D2 — Spec lint fixes are direct edits, not delta specs.** The 5 failing specs get SHALL/MUST wording and `#### Scenario:` blocks that document behavior already implemented and shipped. No requirement's meaning changes, so the delta-spec machinery (meant for behavior changes) would add ceremony without value. The two real requirement changes (planner simulate requirement removed, router-structure route list modified) DO go through delta specs.

**D3 — Scenario content for lint fixes comes from the implementation.** When adding a missing scenario, read the implementing code/tests first and describe actual current behavior — never invent aspirational behavior. If a requirement's actual behavior can't be confirmed from code, prefer the most conservative wording that matches the requirement text.

**D4 — Parallelism via `asyncio.gather` at two levels.** Inside each charger: gather the plug/SoC/power reads. Across chargers: gather the per-charger tasks. Alternatives (TaskGroup, semaphore-bounded) rejected as overkill: N chargers × 3 reads is small (typically 1-2 chargers), HA handles this trivially, and `gather` matches existing codebase idiom. Error semantics must be preserved: today a failed read per charger degrades that charger's fields, not the whole response — keep per-read exception handling inside the gathered coroutines so `gather` never sees a raised exception (no `return_exceptions=True` juggling).

**D5 — History-fetch slimming is flag-only, validated by equivalence.** Set `minimal_response: True` and `no_attributes: True` in the two targeted call sites. `significant_changes_only` stays `False`: the averaging/step-integration math weights values by duration, and dropping intermediate points would change computed averages. `minimal_response`/`no_attributes` only strip attributes/metadata from response entries — the state values and timestamps used by the math survive. Validation: before merging, compare `/api/ha/average` output (and the load-profile vector) computed with old vs new flags against live HA for the same window; values must match. One HA quirk to verify during implementation: with `minimal_response`, HA returns abbreviated entries (no `entity_id`, short keys) for all but the first state — confirm the parsing code reads `state`/`last_changed` in a way that still works, and adapt parsing if not.

## Risks / Trade-offs

- [Some external caller of `/api/simulate` exists outside the repo] → Searched: only archived pages reference it; endpoint has returned an error for months with no complaint. Risk accepted; removal is trivially revertable from git history.
- [`minimal_response` abbreviated-entry format breaks parsing silently] → Mitigation: D5 mandates a before/after equivalence check against live HA, and the parsing code is inspected/adapted as part of the task, not assumed.
- [Slimmed fetch changes averaging results subtly] → Mitigation: `significant_changes_only` deliberately left `False`; equivalence check gates the merge.
- [Gather changes error behavior of `/api/ev/chargers`] → Mitigation: keep try/except inside each read coroutine (D4) so failure modes are identical to sequential code.
- [Spec lint edits accidentally rewrite requirement semantics] → Mitigation: D3 — scenarios must describe verified current behavior; review diff spec-by-spec.

## Migration Plan

Single deploy; no data or config migration. Rollback = git revert. The deleted endpoint/pages/module ship in the same commit as their test updates so the suite is green at every point. Frontend bundle regenerates on build, which drops the stale simulate reference in `backend/static/assets/`.
